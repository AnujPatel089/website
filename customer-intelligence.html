Business Problem

Turn Transaction History Into Customer Decisions

Raw order data is useful operationally but difficult to use directly for retention and customer-value decisions. This project restructures transactional behavior into customer-level signals that support segmentation, churn-risk exploration and value estimation.

Who are the customers?

RFM features summarize recency, purchase frequency and monetary value so customers can be compared using business-relevant behavioral signals.

Which groups behave differently?

K-Means clustering groups customers into four behavioral segments after standardizing RFM features.

How can analytics become usable?

A Streamlit application exposes overview metrics, segment summaries, churn scoring and CLV estimation in one simple interface.

Core Signals

  • Recency: days since a customer's most recent purchase
  • Frequency: number of orders
  • Monetary: total payment value

Why Aggregate Payments?

The notebook explicitly handles the case where one order can have multiple payment rows by summing payment value per order before joining to the order/customer data.

Customer Segmentation

RFM + Standardization + K-Means

The segmentation notebook converts the master transaction table into one row per customer, standardizes Recency, Frequency and Monetary values, and assigns customers to four K-Means clusters.

1. Customer Aggregation

Purchases are grouped by customer_unique_id, using latest purchase date, order count and total payment value.

2. Feature Scaling

StandardScaler brings the RFM dimensions onto comparable scales before clustering.

3. Four Clusters

KMeans(n_clusters=4, random_state=42) generates reusable customer segments that are saved into rfm_data.csv.

Predictive Modeling

Churn and CLV Prototypes

Churn Prototype

The notebook defines churn as Recency > 90, then trains a Random Forest classifier using Recency, Frequency and Monetary values. The serialized model is loaded by the Streamlit application to return a churn score.

Notebook output reports ROC-AUC = 1.0, but that result is not treated as a trustworthy performance achievement because the target is directly derived from Recency and Recency is also used as a model feature.

CLV Prototype

A Linear Regression model estimates Monetary value from Recency and Frequency. The fitted model is serialized as clv_model.pkl and loaded by the application for interactive value estimation.

The repository does not contain a held-out CLV evaluation metric, so no RMSE/R² claim is presented on this portfolio page.
Validation insight: a stronger next churn version should define an outcome from a future observation window and exclude any feature that directly encodes the target rule. A stronger CLV version should use a train/test or time-based validation design and report regression metrics.

Current Boundaries
