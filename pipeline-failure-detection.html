Pipeline Failure Detection AI

A two-stage machine-learning system for SCADA-style pipeline monitoring. The first model detects abnormal operating conditions; the second classifies detected faults as blockage, degradation, leak or surge. A shared inference layer powers both FastAPI and Streamlit while leakage-safe features and group-aware validation preserve credible evaluation boundaries.

Operational Problem

Detect the Failure First, Then Identify the Fault

Industrial telemetry monitoring is not only a classification problem. The workflow first has to decide whether operation is normal or abnormal; only then does fault typing become relevant. The project models that decision flow explicitly rather than forcing every observation directly into a fault category.

Stage 1 — Detection

A binary Random Forest estimates whether an observation represents normal or abnormal pipeline operation.

Stage 2 — Diagnosis

Only abnormal observations are passed to a second Random Forest that predicts blockage, degradation, leak or surge.

Decision Support

The application is a portfolio prototype for SCADA-style replay and investigation. It is not connected to a live industrial control system and is not an operational safety system.

Data & Leakage Prevention

1,000 Observations Across 50 Pipeline Segments

The verified dataset contains 1,000 rows, 50 segments, 17 timestamps and 306 abnormal observations. The model contract deliberately restricts prediction to eight approved telemetry inputs while keeping labels, alarms and grouping metadata out of the feature matrix.

Approved Model Features

  • Pressure
  • Flow rate
  • Temperature
  • Valve status
  • Pump state
  • Pump speed
  • Compressor state
  • Energy consumption

Explicitly Excluded

  • target — prediction label
  • event_type — directly reveals fault category
  • alarm_triggered — encodes an existing alarm outcome
  • timestamp — ordering metadata only
  • segment_id — grouping/response metadata only
Group-aware holdout: training uses 41 segments / 809 rows and testing uses 9 completely disjoint segments / 191 rows. This prevents observations from the same physical segment from crossing the train-test boundary.

Model Development

Two Random Forest Pipelines with Operating Thresholds

The selected binary detector prioritizes failure recall, then F1 and PR-AUC. A separate fault classifier is trained only on abnormal observations. Both saved artifacts include preprocessing and prediction in scikit-learn pipelines and are loaded through one shared inference service.

Engineering Evidence

Shared Inference for FastAPI and Streamlit

The repository is structured as an application rather than a notebook-only experiment. One inference service loads both model pipelines once and serves the same prediction behavior to the API and dashboard.

FastAPI Service

Provides health, readiness, safe model metadata, single prediction and batch prediction endpoints. Batch inference accepts up to 1,000 observations without reloading models.

Operational API Behavior

Every response includes an X-Request-ID. Structured JSON logging avoids telemetry payloads, model contents and local filesystem paths.

Streamlit Workspaces

The dashboard provides Operations Overview, Telemetry & Investigation, and Model & System workspaces with shared replay state, monitoring mode and prediction history.

Automated Tests

The repository documents 85 tests covering validation, leakage boundaries, saved-model integration, inference behavior, FastAPI, operational quality and dashboard behavior.

GitHub Actions CI

Every push and pull request installs dependencies on Python 3.11, compiles src and api, then runs the complete pytest suite.

Self-contained Fixtures

CI does not need Kaggle credentials or raw external data. Dashboard tests use deterministic SCADA-style fixtures across 50 segments.

API endpoints: GET /health, GET /ready, GET /model-info, POST /predict, and POST /predict/batch.

Limitations

Strong Prototype Evidence, Not Production SCADA Validation

Dataset Limitations

  • Only 1,000 observations
  • 50 segments and 17 timestamps
  • Approximately 17 minutes of telemetry
  • Simulated/synthetic-style characteristics
  • Unusually separable patterns may inflate results

Production Gaps

  • No live industrial SCADA integration
  • No prospective field validation
  • No production authentication
  • No production rate limiting
  • No distributed serving layer or industrial governance controls
Portfolio framing: the app performs real-time-style replay of stored observations. It should not be described as live pipeline monitoring or a deployed industrial safety system.
