System Architecture

Detection, Explanation, Investigation and Action Are Separate Trust Boundaries

SentinelAI deliberately separates statistical model output from operational authority. Security telemetry is validated and transformed into causal online features before a frozen LightGBM detector scores attack probability. SHAP, deterministic reason codes and MITRE ATT&CK mappings explain the result; a separate operational risk engine prioritizes it. PostgreSQL remains the authoritative source of workflow and audit state.

RAG & Agentic Investigation

Evidence Before Automation

The copilot and investigation controller are deliberately bounded. RAG retrieves privacy-safe evidence and validates citations. Investigation uses a finite set of typed read-only tools with step, tool-call, duration, evidence and retrieval budgets. It has no arbitrary shell, SQL, Python, external HTTP, scanning or remediation capability.

Evidence-Grounded RAG

Answers are structured around retrieved alert, incident, MITRE, runbook and knowledge evidence. Unsupported attribution questions abstain instead of inventing a threat actor.

Read-Only Investigation

The controller persists evidence, hypotheses, safe operational rationale and reports while enforcing loop detection, contradiction handling and execution budgets.

Human-Approved Actions

AI can propose only validated low-risk actions. Approval and execution are separate authenticated requests with RBAC, expiry, proposal version and target-version rechecks.

Available controlled actions: acknowledge an alert, assign an alert to self, and add an incident note. Destructive remediation, closing/resolving incidents, arbitrary execution and identity/session actions are prohibited.

Security Engineering

Operational Controls Around the AI

Identity & Sessions

Argon2id password hashing, JWT access tokens, rotating refresh sessions, refresh-reuse detection, CSRF protection, TOTP MFA, recovery codes and role-based permissions.

Durable Workflow

PostgreSQL stores security events, analyses, alerts, incidents, investigation evidence, proposals and audit records. Optimistic versions prevent stale workflow mutation.

Observability & Drift

Structured redacted logging, Prometheus metrics, optional OpenTelemetry tracing and privacy-safe PSI drift evidence expose system behavior without putting high-cardinality identities into metric labels.

Logical Recovery

Custom-format PostgreSQL backup, checksums, disposable restore verification, schema/constraint checks and restored FastAPI smoke testing.

Physical Recovery / PITR

Isolated PostgreSQL 17 base backup, WAL archive verification, named recovery target, promotion proof and a deterministic missing-required-WAL failure path.

Limitations

What SentinelAI Does Not Claim

Current Portfolio Boundaries

  • Telemetry and evaluation are substantially synthetic
  • RAG uses a deterministic local provider and in-process index
  • Investigations are synchronous
  • No live SIEM or EDR integration
  • No production high availability, TLS termination or managed KMS
  • No autonomous high-risk remediation

Deliberate Non-Features

  • No arbitrary shell, SQL, Python or HTTP agent execution
  • No Docker, Kubernetes, Kafka, Celery, WebSocket or SSE requirement
  • No automatic model retraining
  • No claim of production certification, production RTO/RPO or formal WCAG compliance
  • Human approval remains mandatory before controlled workflow execution

AI Security with Human Authority Preserved

SentinelAI demonstrates how detection ML, explainability, RAG and agentic investigation can be integrated into a durable SOC workflow without giving an AI unrestricted operational control.
